# 合同

1. 批次持久保存目标目录及保留相对路径选项。只整理本批新资料，不移动跳过的重复资料；文件名、SHA及证据版本不变。复用现有平面目录，以完整路径名称表达文件夹，不伪造树。设置参与幂等身份，续传回读保持。schema42→43只增加导入归档设置，验证旧数据保留及重复重开。
2. GET /v1/document-batches/{id}/sources?offset&limit&q&folder 返回本批当前有效的已发布文字源及文件夹计数；在服务端过滤后计数/分页。页面分组选取并调用既有提案接口。可选source_versions必须和所选document_ids完整一致，列表后版本变化返回冲突，不静默换原文。沿用单提案1–50份合同，不自动全库编译。
3. GET /v1/wiki/maintenance?offset&limit&kind 提供解析失败、索引失败、空文本、同SHA原件、来源变化待办及分类计数。均为明确规则，不称语义冲突/内容正确性鉴定；不自动删改资料。查询不加载全库正文。
4. GET /v1/wiki/pages/{id}/source-changes 提供已采纳页版本、旧/当前publication与revision、变化状态及有界前后摘录。POST /v1/wiki/pages/{id}/refresh-proposal 绑定base_version和source_versions，仅重编译受影响章节，保留其他章节，再进入原审阅。来源不可用不能自动忽略，模型后和采纳前仍检查来源/页面版本。
5. 页面是导入批次→分组选源→提案→审阅→知识页；待更新页→来源变化→更新提案→采纳。摘要/提案不能代替原始证据；页面明确有界摘录不是全文差分。

不纳入本轮：原生图片/音视频、多模态模型选型、自动全库语义去重/冲突裁决、自动重试模型、生产发布或全库质量认证。真实模型语义效果单独验收。
