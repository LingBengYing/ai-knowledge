# 完整装配验收合同

- MC-01：只以`RagApplication`启动，不增加测试Configuration、Bean覆盖、手工Service替身或跳过真实任务发布。显式同时启用摄取、索引、问答、图片OCR/视觉、音频、视频、视频OCR/字幕、摘要/长文件分层、查询附件。配置通过生产环境绑定入口；临时独立数据目录启动前非null，实际目录精确匹配。
- MC-02：空库启动不请求模型/Milvus；运行能力与开关一致。缺失身份仍拒绝；`/health/ready`仍503，不把完整装配作为生产ready。
- MC-03：通过真实HTTP上传合成文本、PNG、WAV和含字幕MP4，等待生产Job/Worker完成解析与完整索引。检查实际authority/typed来源证明音频、视频OCR和字幕没有因配置共存丢失；不能手工写入已解析/已索引状态制造成功。
- MC-04：生产附件入口处理三类实际媒体并辅助已授权库内问答，结果来自库内证据；附件提示不成为答案来源。至少一个字幕问答及一个带可追溯原始来源的摘要经同一进程完成。完整范围、原完整问题和现有证明规则不改。
- MC-05：重启同一独立库后回读答案来源、摘要及原媒体/Range，不重新请求模型；测试保存精确请求计数和原字节断言。所有测试资源受控关闭。
- MC-06：旧1680默认用例与21项当前native身份/多重性保留；最终门禁及源码绑定按既有规范。真实模型效果、真实Milvus多模态质量、中文OCR质量、前端、容器/OS隔离、迁移备份和生产仍单独验收。

本切先增加可复现集成验收，不假设产品必有缺陷；若首次即通过，记录直接验证，不人为破坏配置制造RED。只有实际复现的正常链问题才修生产代码，并保留失败证据后重验。
