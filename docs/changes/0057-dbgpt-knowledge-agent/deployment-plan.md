# 0057 生产部署计划

2026-10-09，负责人在本机交付后明确要求“部署生产吧”，指定服务器并提供SSH密钥。这是本轮发布授权，覆盖本切此前“未授权部署”的阶段边界；不继承其他任务的真实模型试验次数，不自动推送Git。

## 发布范围

现网知识库为0054，独立Java后端及免登录入口。更新为本切配套Java、真实DB-GPT Python服务和Wiki工作台问答；其依赖的0055/0056持久Wiki接口同步发布。既有资料、模型配置、索引指纹和免登录行为保留。不覆盖服务器其他应用或默认HTTPS端口。

## 正常路径与验收

1. 只读核对旧制品摘要、运行身份/环境路径、公开入口、数据库schema/完整性/活动任务。
2. 准备独立不可变制品、固定Python运行时与锁定依赖；重跑发布相关验证并如实保留未通过项。对实际定制入口验证Wiki/Agent精确路由和原免登录身份，不能直接用开发代理上线。
3. 上传新release，逐文件摘要核对。Python只监听loopback18088，使用固定Java18084回调，独立运行账户不能读取资料/服务商密钥。共享service token在服务器生成，私有配置注入，不回显。
4. 在真实SQLite一致副本演练schema30→32，核对旧业务行与文件不变及新表/迁移登记；不调用模型。用真实systemd账户检查全路径遍历与运行文件读取权限，DynamicUser从活动PID读取UID/GID。
5. 入口关闭后停止后端，完整备份数据/配置/密钥/两unit并核对；没有活动任务才能切换。新后端启动迁移后，入口开放前再次核对旧业务数据不变。启用Agent，验证Python健康、Java健康、公共配置和持久只读接口，再开放入口。
6. 从公网HTTPS和实际浏览器核对已发布Wiki工作台、Agent配置、资料列表及旧原文回读。自发验证不提交真实问答/索引/编译，避免消耗未具名云额度；真实模型质量保留未验证。

## 回滚

旧0054最高schema30，不能在32上盲目恢复旧JAR或手工降低版本号。迁移后尚未开放且能够证明没有新增业务写入时，失败自动恢复停机一致备份及旧unit。入口一旦开放，不恢复旧数据库；使用本次已验证的schema32兼容JAR关闭Agent并恢复旧入口，保留用户新写入。旧制品、停机备份和完整新release持续保留。

真实端口、版本、制品摘要、运行身份检查、迁移/回滚演练和公网结果另写deployment-verification.md。部署动作成功不等于真实模型质量、全量覆盖率或长期稳定性验收。
