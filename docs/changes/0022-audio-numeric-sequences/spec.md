# Spec

1. 十进制数字（含全角数字）之间的 ASCII/中文逗号序列保持为一个原始字段值，可有 ASCII 空格/Tab 但不跨换行。`Project Car launch code is 7,3,9,21.` 对 Car 的已支持问题须保留原序列及准确引用；不能只答第一项 `7`、拼成 `73921`、转换原数字/标点或补成其他主体。
2. 仅包含首项或前缀的模型摘录不足以证明该完整字段，整体拒答；未引用的上下文只用于否决，不自动扩充摘录。
3. Cedar 问题不能用 Car 转录证明。完整序列尾部有不同值时保持冲突拒答，混合数字序列不因为局部三位组去逗号而变成另一原值；只允许完整合法千位分组 token 沿用既有表示等价。
4. 英文数词原文、千位分组、正负/小数/单位含义保持；数字以外的普通语句逗号继续分字段，序列之后另一赋值不能加入前一字段，不泛化为保存所有逗号。仅完整合法 ASCII 千位分组 token 沿用原表示等价；混合组、横向空白或全角数字/中文逗号原值不做猜测转换。条件、否定、更正、冲突、示例和指令规则及已有中英文正反例须完整回归。
5. 新证明语义使用明确 policy revision，历史 trace 不改写。仍通过现有 AnswerService 形成答案、authority trace 和 typed 原音频来源；没有生成值补全、新运行开关或模型调用。
6. 本批本机行为验证不能认证 ASR 实际识别、真实模型/Milvus质量、已部署或公网通过。主线已准备新清晰合成样本，但当前协调要求仅只读核对计费/既有台账、不增加模型调用；本轮真实复验为 NOT_RUN，新的调用数为 0。

数字排除边界：`is/are not` 后为完整数字逗号序列时不能证明实际值，该上下文仍可否决冲突的正断言；普通负状态与名称按原合同保留。不是通用否定语义升级。

指令边界沿用既有合同：同字段/前置指令不能证明事实；逗号后的独立指令不替换已引用的完整原事实，其要求的 `73921` 或只有指令的摘录不能证明问题。不能将有效事实与独立恶意内容共存等同于“只有提示注入”。
