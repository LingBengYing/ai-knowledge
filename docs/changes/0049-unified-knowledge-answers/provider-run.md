## 已定位原因与未能证明的部分

`QuestionFacts.procedureQuestion` 只识别前置“如何/怎么”、末尾“怎么/如何操作”等句型，不识别“产品名 + 如何 + 操作”。因此原问题在 `TextGrounding.verifyText` 返回 `unsupported_question`，发生于摘录之后、综合生成之前。HTTP 200 及该终态不代表摘录内容质量已通过；未保存模型响应正文，不能断言模型实际选中了哪些句子。

进一步只读核对已保存合成原文：PDF 第 1 页是“适用产品：青榆X1桌面净化器”，以及编号的“开机 / 开启夜间模式 / 确认开启”标题和分行操作正文；现有 `ProcedureFact` 还要求“操作名：正文”结构。因此只加问句正则仍不能完成当前样本的证明，不应以换一个拒答码冒充修好。

视频 ASR/字幕只有短按电源、长按月亮键 3 秒、月亮指示灯变绿三条操作，没有产品名。不能删掉问题主体、把文件名当原文证据，或从 PDF 无条件搬用产品身份来强行增加视频引用。

此外，当前 `KnowledgeAnswerService.propose` 仅把已证明摘录对应的原上下文传给综合；`OpenAiCompatibleModels.verifySynthesis` 又筛为最终引用的上下文。当前核验包含原问题、每段实际引用和完整段落，但不是全部检索原上下文。后续自然语言证明方案必须保留所有已授权检索上下文作为限制/反证材料，不能通过简单删除旧 grounding 门禁解决当前拒答。
