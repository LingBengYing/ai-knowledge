## 配置分工

嵌入、重排、生成三个文字角色通过网页“设置”填写、保存、测试并明确应用，见[模型设置](MODEL_SETUP_AND_RETRIEVAL.md)。媒体功能无需再向旧环境重复复制这三个文字角色的模型名称或密钥。

视觉模型、语音转录、解码器和独立媒体向量仍由服务管理员按已有配置提供，不改为网页文字模型，也不共用或推测其密钥：

| 媒体能力 | 仍需提供的独立配置 |
| --- | --- |
| 原图理解 | `RAG_VISUAL_ENABLED`及`RAG_VISION_*`，参数见[原图知识库](VISUAL_LIBRARY.md#配置) |
| 音频转录 | `RAG_AUDIO_*`中的ASR模型、凭据及FFmpeg/FFprobe路径，见[音频配置](AUDIO_COMPILATION.md#本机上传与索引开关) |
| 普通视频画面和语音 | `RAG_VIDEO_*`中的解码器、ASR及Vision，见[视频配置](VIDEO_PUBLICATION.md#配置) |
| 独立图片/音频向量 | 各自模型、固定版本、维度及独立向量库配置，见[原图向量](IMAGE_VECTOR_RETRIEVAL.md#配置)和[原声向量](AUDIO_VECTOR_RETRIEVAL.md#配置) |

引用指南中的媒体参数继续适用；旧指南要求复制完整文字环境配置的前置条件，由本轮网页配置装配替代。媒体开关、摄取/索引/问答开关、运行环境和地址限制仍按原合同执行。参考附件也仍需其已有独立配置；独立声音与原视频音画不因此自动开启。

资源构造与配置应用本身不调用模型、不创建远端索引。只有用户明确测试连接、导入处理、建立索引或提问时，才按对应流程调用服务，可能产生费用。缺少某种媒体资源时，不应宣称相应能力可用。

## 正常操作

1. 管理员准备需要的独立媒体资源和向量库；用户在网页保存三个文字角色并明确应用。
2. 页面读取最新能力。按实际开放的上传类型导入图片、音频或视频，查看解析任务。
3. 解析完成后明确建立索引，等待服务器发布。独立声音或原视频音画沿各自详情中的显式建立入口。
4. 在知识问答选择与资料相符的证据模式和完整范围，明确提问。点击引用，核对原图、页码或时间片段，再打开原件。

缺少入口时先核对实际运行版本、媒体资源和能力开关，不通过重复保存文字密钥、重复上传或假设文字生成模型能处理原图/声音来绕过。真实页面和模型效果仍待用户在完成构建、部署后验收。
