# Spec

1. 统一问答在摘录校验前按完整问题选择一次主题或已有事实路径；不以旧证明失败为主题fallback。短裸主题如Project、英文名词短语、中文主题和型号可走主题路径；不硬编码具体产品或项目。
2. 金额/日期等明确字段以及带疑问、数量、权限、条件、否定、步骤、多事实的提问保持旧路径。旧TextGrounding/QuestionFacts协议不放宽；主题只用于统一知识问答。
3. 新小Module TopicEvidence仅准入真实摘录：授权候选ID、完整上下文身份及预算、精确唯一子串、服务器码点区间、完整字段/句子、每条摘录中的完整主题锚点（英文/型号边界）共同成立。不能以文件名/标签/相似度或另一来源补证。
4. 来源指令/伪造定位/切断条件继续拒绝。主题准入不是最终事实认证：现有综合和独立核验必须全部通过；所有已授权召回原上下文作为context_only限制/反证，不能新增无引用事实。仅有名称证据可以只回答资料中的名称。
5. 不新增模型请求步骤、不改旧extract PROMPT或索引模型revision；主题策略和综合提示独立版本化。原ACL、完整scope复验、版本/原件SHA与typed引用、终态trace和来源回读保持。
6. 发布源为线上fabc5a6的隔离快照，仅叠加本修复与必要完整上下文合同。只替换后端运行包，前端、环境配置、SQLite资料及Milvus不迁移/重建。备份并记录原包与健康状态，失败回切旧包。
7. 验收包括实际Project原页的红→绿、其他主题、旧日期/预算正控、引用/注入/条件拒绝、Service经综合核验后释放以及来源回读；相关完整行为测试和必要发布回归。实际线上模型质量只有获批并执行后才记通过。
8. 真实复验须能核对两个服务商的实际HTTP尝试。共用Transport只记录随机尝试ID、固定服务商/操作类别、HTTP状态及耗时，不记录URL、模型输入输出、凭据、原始错误；发送前保守计次，失败无重试。一次综合问答路径最多嵌入1、文档/视频重排各1、摘录/综合/核验各1；这些上限不构成其他问题或批次的授权。
