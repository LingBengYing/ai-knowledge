# Spec

1. 登录仍必需，组织仍由受验证身份确定。组织内所有已登录成员具有相同资料读取、维护和模型配置能力，不再由角色名/逐文档授权决定；不得把其他组织或已删除资料纳入可用资料。
2. 普通知识问答与召回测试默认且固定全组织现有可检索资料，不提供手动文档范围。旧请求中的document_ids作为已废弃参数处理，明确不再限制本入口范围；不得冒称仍提供私有选中资料问答。
3. 普通知识问答收敛为检索原文→一次模型综合→服务器真实来源。取消通用入口的手写问句分类、强制摘录、逐条主题关键词、字段证明及二次模型核验硬拒答。不宣称模型回答已独立验证，资料不足允许说明已知部分及缺失，不用模型常识冒充资料。
4. 删除问题/回答的人为字数、段数等业务上限；取消全库128份的总量门槛，检索实现可分批，不把TopK理解为权限范围。运输解析、实际服务商上下文和物理资源边界必须准确说明，不能谎称计算机可处理无限输入。
5. 来源只从本次真实检索候选生成，模型不能自造页码、时间或URL；不再要求每一条引用重复问题全文。保留资料原版本、撤下/删除状态与配置一致性，文档内容作为数据。
6. 前端移除问答/召回范围与角色管控文案，不影响管理列表的目录/标签筛选、登录/退出和模型配置秘密保护。
7. 新合同用新正反例验证：同组织第二账号无逐文档ACL也可读写；未登录/错组织仍拒绝；旧document_ids不能缩小全库；自然问句走一次综合而不摘录/核验；真实来源仍可回读。旧严格入口的历史测试不冒称新普通RAG的质量证据。

验收边界：该变更不是完整生产验收；上传/解析的物理字节、超时、并发等资源参数另列清单，不为“全部去掉”设置无界内存/进程分配。未实际移除的限制必须在REVIEW明确保留，不得宣称所有限制已消失。
