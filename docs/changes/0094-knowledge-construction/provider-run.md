## 根因与修复

v1的概览同时引用guide和care，guide章节仅引用guide，care章节仅引用care。guide更新后，概览确实需要guide+care两份上下文。旧实现只圈定输入文档集合，仍调用“整页编译”模型合同；模型据两份原文生成三个章节后，服务又追加原来的care章节，造成重复。

修复没有删除必要的care上下文、按标题猜测去重或直接补填模型未引用的来源：

- 新操作 `revise_wiki` 使用同一OpenAI兼容chat/completions，单次调用。
- 输入含明确受影响section_id、旧标题/正文、当前允许证据及 `required_evidence_groups`；每组代表一份原资料的别名集合，至少引用其中一项，允许多片段只选相关片段。
- 输出必须覆盖全部且仅目标章节，各恰好一次；未知、遗漏、重复、跨目标来源和缺少某份原资料组均拒绝。
- 服务按原ID和原顺序替换受影响章节；未变章节的ID、标题、正文和来源完整保留。来源/页面/模型配置并发检查与采纳前验证不变。
- 原文摘编是独立零模型策略，保持逐片段原文，不将整文档重复拼入目标章节；按精确publication+reference排除已保留片段。

r2相关54项本地回归全部通过（模型11、服务40、实际HTTP3）；随后独立的一次真实 `revise_wiki` 语义和浏览器采纳也通过，二者分别记录，不用替身结果代替真实结果。
