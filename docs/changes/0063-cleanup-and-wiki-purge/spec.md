# 行为合同

- 保持现有 Controller→Service→Repository/Model 分层，复用认证、同组织边界和全操作维护栅栏。
- 原始资料清理复用单项/批量 cleanup API 和后台资源账本；生产显式启用既有 removal/cleanup 配置。修正当前 managed 初始文字索引 target 不能被清理配置识别的问题，必须完整身份匹配，不猜历史目标。
- 接受清理即撤出列表/检索/来源；本地正文和原件实际清除后显示其资源结果。Milvus 逻辑删除不等于远端物理回收，尚无证明仍显示未核实，不伪造 completed。不扩大现有 production/readiness gate。
- 新 DELETE `/v1/wiki/pages/{id}/purge?version=N&lifecycle_version=L` 无 body，返回 200 `{page_id,state:"purged"}`。仅同组织、已 deleted、双版本 CAS 可执行；active/版本冲突409，不存在/跨组织404。
- 仅删除目标派生页的全部修订、提案和生命周期数据；以事务内窄 permit 放行对应不可变删除保护，其他更新/删除保护保持。保留无正文的删除审计，不保留被删除页正文，不删除原资料或索引。
- 永久删除后当前、历史、恢复、搜索及提案读取不可再取得该页；重启保持。新 schema35 迁移不删除既有业务数据。
- 页面在已删除列表和详情显示“彻底删除”，确认明确不可恢复且原件保留；取消零请求、失败保留当前项、成功刷新列表，无自动重试。资料维护清理入口与服务真实 capability 对齐。
- 发布前保留旧包、配置和数据库备份，验证迁移和回滚办法；不恢复旧备份覆盖部署后用户写入。免登录定制保持。0048已完成的查阅进度界面随当前前端一并发布，不披露内部推理。
