# Spec: 索引完成才发布

1. 默认关闭，`RAG_INDEXING_ENABLED=true`显式开启且仅loopback开发/test；启动验证完整TextAdapterSettings及固定workspace、embedding revision/dimension和Java专用collection。配置失败不退到假模型/内存向量库，也不调用生成/重排。模型key不进代码、HTTP、审计、argv或日志。
2. 对已解析真实资料显式POST `/v1/documents/{documentId}/index`（无query/body），创建者须当前editor/owner。合成行、未解析行、已有索引任务或已有active发布均拒绝；不隐式重建或覆盖已发布版本。本切一个document一个索引任务，失败/取消仅在同冻结配置内重试，最多3次；未知/无权读取任务统一404。GET `/v1/indexings/{taskId}` 与POST同路径 `/cancel`、`/retry`。
3. authority仍由ManagementModule持有唯一连接/进程锁。v1/v2须一致性备份后增量迁移到v3；不重建/削弱v2不可变页、segment、source和revision约束。新增索引任务、不可变attempt台账、publication、完整source→physical→digest映射及active publication sidecar；不使用legacy注册revision或v2恒null字段冒充active。缺少generation列或映射/attempt台账的早期未发布WIP v3拒绝打开，不自动猜测升级。迁移失败不自动覆盖/恢复原库，回滚使用独立旧版备份并明确新增资料不在旧备份中。
4. task绑定doc/source revision/source hash/parser/embedding identity/projection identity，含attempt、随机claim token摘要、创建者、时间与安全错误码。每次queued→processing领取时产生新的UUID projectionGenerationId并写入不可变attempt台账；它与source revision及claim token分别承担不同身份。queued→processing→indexed/failed/cancelled；取消/重试使旧claim无效，重试保留source证据并清空待重新领取的generation，最多3次。重启将processing变成可重试失败，不自动重放模型开销。领取和完成时验证同一不可变解析版本及创建者当前写权限；完成还须核验当前attempt/generation台账，旧generation回执永不发布。
5. 索引在独立Java进程进行，不持有authority连接、不在HTTP线程或DB事务内调用模型/Milvus。父进程传递有界的权威segment快照、projection generation和显式模型/Milvus配置，清空继承环境；不传JWT、数据目录、任意用户路径或其他环境变量。stdin/stdout使用有界protocol v2，绑定父PID/startInstant，日志不污染协议；固定JVM资源、全任务deadline、单索引并发、取消/超时终止并等待。独立main的watchdog在父消失/超时后终止worker；同JVM run只中断调用者，不终止宿主。固定/tmp、同OS用户、同规范化endpoint/database/collection的协作进程以POSIX文件lease串行远程处理；等待也计入总deadline，同JVM等待者不能释放其他持有者的OS锁。lease inode永不unlink，权限/owner/symlink/hardlink检查失败拒绝执行；父崩溃私有job临时目录仍需受控回收。终止worker不能撤回已被上游接受的请求，进程分离及lease都不是OS沙箱，生产需另行隔离验收。
6. 按小批次（至多16段）嵌入和upsert；模型数目/维度/有限值及完整upsert receipt沿用严格校验。整个source revision最多4096段，失败时保留原解析证据但不发布；已写入的未发布投影对未来授权scope不可见。Milvus的revision_id保存本次projection generation，physical segment ID由共享physicalSegmentId(generation,sourceSegmentId)以带域标识、长度前缀的SHA-256确定性导出。同attempt物理身份稳定，不同attempt不能复用物理ID；旧请求晚写只影响旧generation，不能覆盖新发布投影。不自动删除现有Milvus集合/记录，也不修改source revision/segment ID。
7. full revision验证不是ANN抽样：此处远端revision即projection generation，以精确generation filter读取N+1上限的完整metadata集合，逐行验证workspace/doc/generation且与期望的全部唯一physical ID严格相等；只按generation取metadata是为了连错误scope的额外记录也能发现，不能用更窄过滤隐藏它们。再按精确ID小批次回读text+dense，校验每个scope/text/float32向量的规范化摘要，拒绝少行、多行、重复、错scope、正文/向量变化、超限、超时和取消。所有调用在同一总budget内，首尾核对完整metadata、schema、两个索引的类型/度量/Finished状态。实际Strong由collection Describe校验，不把未识别的Query请求参数当Strong证明；真实版本仍需外部验收。索引写入至发布需同generation单写者以及collection/schema/index配置冻结；多HTTP调用不是跨请求数据库快照。
8. worker结果含完整physical entry摘要清单及绑定projection identity/manifest hash/count的验证回执。authority从权威source segments和当前generation重新构造完整physical ID清单，核验全部ID、数量、claim/attempt/generation台账/target/source/parser身份；同一事务创建不可变publication、每条source→physical→digest entries、active pointer和审计，再置indexed。active_revision_id仍是source revision；未来AuthorizedScope必须从active publication取得projection generation，候选通过该publication entries映射回权威source证据，不能把source revision直接当远端filter。回执是可信内部Adapter的校验结果，不是来自用户的签名生产attestation；外部HTTP不能直接提交回执或设active。
9. 列表增加独立index_status/latest_index_job/index_publication_id/可索引能力；active_revision_id只来自已验证publication，包括合成资料也不得返回legacy版本号作为active。合成资料原注册身份以registered_revision_id保留，真实资料此字段为null，数据库原值/源hash/文件名不变。整理不改源身份或调用任何模型。问答/来源仍未实现时can_answer=false、全局answers=false，ready503/production拒绝继续有效；网页必须区分解析与索引，不显示假问答成功。
10. 保留190Java、42Java仓库Node/58独立前端测试与四PDF六golden；新增先失败后通过的migration/权限/claim/部分写入/完整manifest/真实进程/HTTP/浏览器验证。最后源码变更后完整verify、80%行分支门禁、独立审查、源码指纹和真实模型/Milvus验收分别记录，不能把stub结果当真实集成。完整文本golden必须等最终答案链路可运行后执行。

未来答案约束不缩减：每个回答事实有支持、与问题主体/谓词相关、保留数值/否定/条件语境，全部所问事实被覆盖，否则整体拒答；冲突不能任取一个。服务器locator与最终完整selected-set/ACL/active复验同事务审计。原文摘录非空不等于上述证明，多模态和生产目标不变。
