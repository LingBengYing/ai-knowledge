# 行为合同

1. 持久批次清单先登记文件名、字节数、SHA；文件分开上传，避免巨型multipart驻留内存。
2. 同一批次槽位同字节重复上传只回读已存在任务；不同字节拒绝，不创建重复资料。
3. 文件提交后自动解析/索引；上传不等待模型。批次状态从权威任务表派生，可分页回读。
4. 解析和索引默认各2路、最大4路，上传默认2路；在途数量有界，不把几千个任务变成几千个线程。
5. 不同资料可并行，单资料发布/配置切换/删除维护仍受既有版本和维护合同约束。
6. 集合初始化持短独占租约；正常索引按资料/generation隔离，embedding网络等待不持集合锁。
7. 模型请求日志携带权威索引任务和资料编号；批次预留嵌入请求额度，失败后不自动重试。
8. 向量继续按批写入，完整版本校验后独立发布；某资料失败不撤回已成功资料。
9. 同批任务进度与重开回读、2路真实执行重叠、并发峰值、版本一致性及失败分支以本地受控HTTP验证。

Spring Batch评估：参考其分块/背压思路；本切复用现有SQLite持久任务和claim fencing，
不再引入第二套JobRepository/恢复策略。未来需要跨节点分区作业时再接Spring Batch。
