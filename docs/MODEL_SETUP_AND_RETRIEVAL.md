# 文字模型配置与召回测试

当前正常配置支持逐角色服务商：[0037](changes/0037-model-providers/spec.md)。嵌入、重排使用硅基流动；生成可选硅基流动或 DeepSeek 官方。每个角色的模型 ID 与密钥必须属于所选服务商。此前统一硅基流动的草稿如填写了 DeepSeek 官方密钥，应明确选 DeepSeek 官方并重新填写该密钥后保存、应用。自动化测试已停止，本轮构建与页面验收状态另记。

当前0039增加“重建索引并应用”流程，适用于已有资料后更换嵌入模型、明确版本或维度，见[操作说明](MODEL_INDEX_REBUILD.md)及[本轮记录](changes/0039-model-index-rebuild/REVIEW.md)。本次说明更新时后端仍在编译前整合，尚未构建、测试或部署；旧本机验证不认证本轮修改，页面由用户验收。

保持当前嵌入配置时，已有索引资料可按服务器资格，在行或详情点击“重建文本索引”。已建立独立图片/音频向量的资料在相应能力开放且材料完整时，也可重建文字索引并核验后继续使用原媒体向量，不重新生成媒体向量。无需重新上传或解析，失败或取消保留旧索引；请求结果未知先刷新。更换嵌入模型或维度使用设置页“重建索引并应用”，由一个批次完整处理后统一切换，不能逐份普通重建后提前应用。

后端0032与独立前端0021提供“保存配置 → 测试连接 → 应用配置 → 导入并索引 → 测试召回 → 问答及来源”的基础流程。[0032验证记录](changes/0032-model-setup-retrieval-test/verification.md)仅说明该历史版本；本机协议替身通过不表示本轮修改、真实供应商或当前部署已通过验收。

0033角色切换增量为 `LOCAL_VERIFIED`，未部署，合同见[角色切换规格](changes/0033-text-model-role-switch/spec.md)。本轮3058项Java测试全部通过，原LINE/BRANCH双80%及架构门禁通过；真实本机Spring/SQLite/HTTP正常链已验证生成、重排实际切换、新trace、原索引与来源保持、重启恢复及嵌入变化拒绝。供应商和向量库使用本机合成协议服务，新增真实provider调用为0，实际部署后的页面由用户验收。旧0032中仅更换生成或重排模型仍可能返回 `model_rebuild_required`。

## 服务配置

显式启用 `RAG_MODEL_CONFIGURATION_ENABLED=true`，并将 `RAG_MODEL_CONFIGURATION_ADMINISTRATORS` 设为本组织模型管理员的真实 actor ID，以逗号分隔。资料 owner/editor 不自动成为模型管理员。仅允许 development/test 及字面 loopback 绑定；JWT/会话和独立前端代理沿用原配置。

硅基流动端点由 `RAG_MODEL_CONFIGURATION_PROVIDER_BASE_URL` 配置。DeepSeek 使用官方端点；可信旧环境中的官方根地址或 `/v1` 形式会保留，浏览器不接收 URL。`RAG_MILVUS_ENDPOINT/TOKEN/DATABASE/COLLECTION` 由服务器配置，页面不接收向量库 token。Milvus 缺配置时仍可保存草稿、测试三个文字模型；应用配置和召回需要完整投影设置。保留摄取、索引、问答各自的开关，需要完整文字流程时显式启用 `RAG_INGESTION_ENABLED`、`RAG_INDEXING_ENABLED`、`RAG_ANSWERS_ENABLED`。程序不自动读取 `.env`；[.env.example](../.env.example)仅为变量说明。

不必先在环境配置三个文字模型。无已应用配置时，管理页面仍能启动并显示设置入口；索引、问答及召回提示先配置。完整旧环境模型可导入为草稿，仍须明确应用。原来的运行方式在本开关关闭时保持有效。

## 页面操作

在独立前端“设置”中读取当前配置，为每个角色选择服务商、填写模型 ID。嵌入还须填写实际维度和明确版本。同一服务商密钥留空可保留；更换服务商须重新填写该服务商密钥。保存只产生草稿，不调用模型；密钥存入数据目录下的 `private-model-settings/text-models.json` 私有文件，不回显、不出现在资料原件目录。需要对该私有目录单独安排凭据备份与轮换。

对已保存版本分别测试三个角色；每次只发所选角色的一次合成输入请求。向量库测试为只读连接检查，不证明集合 schema 或索引完成。应用是独立动作，不隐含测试、自动索引或生成答案。

应用成功后可点击“去导入资料”，选择原文件并确认上传。等待解析成功后，在资料行或详情明确建立索引。进入知识问答，填写问题与完整资料范围，设置返回数和是否重排，点击测试召回。结果包含真实片段、文件、页码、码点位置和排序分数，可以核对同版本原文件，再保留问题与范围继续问答。召回测试不调用生成、不创建答案引用；RRF/重排分不是置信概率。

## 已有索引后的角色切换（0033本机已验证）

保持嵌入端点、模型名称、明确版本、维度以及服务器投影目标完全相同，只修改生成或重排模型。读取当前配置后编辑该角色，密钥留空保留已有值；依次明确保存、测试所改角色、应用。0033合同允许在能够证明原索引身份一致时切换，保留已发布索引、任务和历史答案来源；应用不重新嵌入资料、不写投影、不自动问答。

应用成功后，主动测试召回以核对新重排角色，或发起问答以核对新生成角色。主动检索仍会调用查询嵌入，不能把“不重建已存资料”理解为后续查询不调用模型。嵌入参数变化时普通应用仍拒绝并保持旧配置；现在可按0039的[重建操作](MODEL_INDEX_REBUILD.md)，保存草稿后明确创建批次，全部完成再自动切换。无法证明旧索引身份等资格问题须先处理，不要删除资料或重复应用来绕过。这不会切换独立多模态模型；既有媒体链仍核对实际完整模型profile，可用入口以实际服务capability为准。

## 角色切换后的媒体来源（0034）

已有图片或视频答案后，仅切换文字生成或重排模型，原来源可以继续按当前权限打开。来源能力与新问答能力分别显示：即使 `visual_answers`、`video_answers` 已关闭，服务器已装配的 `visual_sources`、`video_sources` 仍可用于读取已有来源。

这一步不会重新解析、生成答案或重建资料。图片引用读取原图；普通视频和OCR引用仍可读取原视频与保存帧；字幕引用读取原视频和保存的字幕时间，原来没有帧的引用仍没有帧。权限撤销、完整原范围失效或原件校验失败时，应重新核对资料，不能把旧来源当作当前可用。

文字角色切换不会自动更新独立媒体模型。已不兼容的新媒体问答、附件及处理入口继续明确返回 `media_text_configuration_mismatch`，由管理员核对实际媒体配置；不要重新上传或重建资料来尝试打开历史来源。0034本机回归进度见[验证记录](changes/0034-media-role-switch-sources/verification.md)，实际页面仍由用户在部署后验收。

## 失败与恢复

| 提示 | 处理 |
| --- | --- |
| 字段无效 | 按提示修改安全字段，再明确保存 |
| 模型鉴权、限流、超时或协议失败 | 核对对应角色；失败不替换当前运行配置 |
| `configuration_conflict` | 重新读取配置后编辑，不自动重发写操作 |
| `configuration_busy` | 等实际操作结束后再次明确应用 |
| `model_rebuild_required` | 旧配置保持有效；读取重建资格，明确“重建索引并应用”，或先处理页面提示的任务、权限及材料问题 |
| `model_rebuild_in_progress` | 等当前批次结束或刷新进度；不要重复提交，旧配置及已发布资料继续使用 |
| `model_rebuild_failed` | 旧配置及旧资料保持可用；刷新状态、核对原因后，可按服务器资格明确创建新批次 |
| 保存或应用结果未知 | 先读取当前配置核对版本，再决定下一步 |
| 召回范围不可用 | 修正完整范围或权限后重新测试，不自动删去失败资料 |

私有配置文件损坏时返回明确不可用，不以旧环境或空配置覆盖。重启恢复已应用版本时不发模型请求。独立前端页面验收步骤见该仓库 `docs/MODEL_SETUP_AND_RETRIEVAL.md`。
