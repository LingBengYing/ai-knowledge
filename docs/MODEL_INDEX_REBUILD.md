# 更换嵌入模型后重建并应用

0039提供设置页的“重建索引并应用”，用于已有资料后更换嵌入模型、明确版本或维度。仅更换生成或重排且原嵌入目标兼容时，仍可普通应用。合同见[0039规格](changes/0039-model-index-rebuild/spec.md)。

截至本次说明更新，后端仍在编译前整合，尚未完成构建、测试或部署；前端已接线，页面由用户验收。未运行自动化测试、语法检查、浏览器验收或真实模型调用，后续实际状态见[REVIEW](changes/0039-model-index-rebuild/REVIEW.md)，不能借用旧测试证明本轮功能。

## 正常操作

1. 在设置页读取配置，填写新的嵌入模型、明确版本和实际维度，保存草稿。旧已应用版本保持有效。
2. 用户按需明确测试已保存的模型与向量库连接。测试只证明对应连接结果，不建立资料索引。
3. 页面读取本次重建资格和资料数量。配置管理员必须能编辑完整受影响资料；已有未完解析、索引、原件更新或清理应先结束。
4. 用户核对调用费用，明确“重建索引并应用”。服务器创建一个后台批次，使用完整保存的解析材料，不重新解析或ASR；新模型和向量服务调用可能产生费用。
5. 页面显示已构建数量。处理中旧配置和旧publication保持有效，可查询、打开旧来源和整理；配置保存、导入、原件更新、删除与索引写入暂停。离页仅停止页面轮询，返回后可恢复状态，不会取消或重复创建后台工作。
6. 全部材料建立并验证完成后，服务器统一发布并自动应用。页面回读确认有效配置和授权资料，再提示重新召回或提问。无需第二次应用，也不通过逐份普通重建提前切换配置。
7. 用户以原问题和完整范围重新测试召回、问答，打开新版本来源。问题、范围及整理草稿保留；旧答案来源按当前发布规则重新核对。

已有独立图片/音频向量会完整核验并映射到新文字索引，不重新调用媒体嵌入模型。独立sound/video_av处理图保持不变。批次使用完整服务器范围，不能按当前管理页面的分页或筛选静默缩小。

## 失败与恢复

失败或重启中断保留旧配置和全部旧publication，不自动重试。`model_rebuild_in_progress`表示已有批次，等待或刷新即可；`model_rebuild_failed`表示本次未完成，应核对安全提示，再按资格明确创建新批次。提交结果未知时先GET回读，不能因没有收到202便重复POST。

GET/POST `/v1/model-configuration/rebuild`使用普通10秒期限；POST仅提交已保存的`version`，返回受理状态。后台批次进度不靠保持长连接。接口能力为`model_index_rebuild`，旧配置摘要和单角色测试协议保持。
