# 续验契约

- 输入：已存在的合成视频`sample.mp4`，完整单份资料范围，普通视频画面模式。
- 正常路径：资料行进入提问→明确提交原问题→读取回答或安全拒答→成功时打开服务器来源核对原帧及时间。
- 本轮最多提交2次普通页面问答。这是页面提问次数，不冒充底层多个模型请求的计数；每次沿既有生产预算，无自动重试或新增附件/索引/ASR。
- 只读已有部署的Java日志，提取`stage`、白名单`failure_code`与累计`elapsed_ms`，不保存问题、答案、原件或异常正文，不读取密钥配置。
- 自动化测试、检查及审计继续停止。没有复现或具体诊断依据时不猜测、放宽证明或宣称修复。生产、完整ASR质量、未验PDF访问等原边界保持。

## 实际正常路径阻断的最小修复

第1次页面请求得到`unsupported_question`。现有颜色问句语法要求“分别/各自”，普通单主体中文“背景是什么颜色”会落入不支持的关系分支，在视觉草拟前被拒绝。本轮补单主体“是/为 + 什么颜色”问法，保留完整主体并复用现有`ColorFact`，不是删除全部疑问词或改写原问题。

新增问法不拆除现有共享颜色、多事实、条件上下文或颜色值校验。复合主体与时间/条件问法不由新分支简化为单个无条件事实。共同事实身份、原问题SHA、完整范围、逐事实核验和JOINT双模态贡献规则保持；不硬编码白色或样例文件。改变的语义版本明确升级，不修改provider、数据库或前端。

按负责人停测指令只构建跳过测试的运行包；共享语义旧回归未运行，不能宣称冻结或全量回归通过。剩余1次页面提问仅在明确运行新包后用于原正常问法，旧失败不抹除。
